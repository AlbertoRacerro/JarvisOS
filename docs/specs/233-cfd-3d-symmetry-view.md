# 233 — CFD 3D symmetry view

Status: ready
Depends on: none

## Goal

A finished pipe CFD run shows its computed quarter domain in 3D in the Design Results view: the wall surface, both
symmetry planes and three axial cross-sections, colour-mapped by pressure or speed, with a legend and a click probe.
The full pipe can be shown by mirroring the quarter. Mirrored parts are always labelled as reconstructed, never as
computed. Today only the z = 0 axial section is exported, and it is drawn as a 2D heatmap.

## Why

Item W1 of the COMSOL-direction roadmap (`docs/strategy/ROADMAP_COMSOL_DIRECTION_2026-10-30.md`, sections 3 and 7),
queue item 4 of maintainer directive `L20261103141101-7c11`. It is the smallest workbench step with high value: it reuses
the solver, run records and three.js viewer that already exist. The symmetry is exact for this study (see the
`casegen.py` docstring), so mirroring is honest only while the run records that the domain is a symmetric quarter.

## Scope

In scope:
- A second `surfaces` function object, `pipe_fields_3d`, in the generated `controlDict`. It writes ASCII legacy VTK for
  the `wall`, `symmetry_y` and `symmetry_z` patches and for `cuttingPlane` sections normal to x at 25 %, 50 % and 75 % of
  the pipe length, with fields `p` and `U`, `cellPoint` interpolation and the same write control as `pipe_fields`.
- `symmetry` metadata written into `run.json` when a run starts, taken from `casegen` constants rather than inferred
  later: `{"domain": "quarter", "axis": "x", "mirror_planes": ["y=0", "z=0"], "basis": "<one line from casegen>"}`.
- A reader, built on the strict parser in `field_export.py`, that returns one entry per surface. Each entry has its name,
  kind (`wall`, `symmetry_plane` or `section`), points, polygons, `p`, `U` and `|U|` with min and max values, units and
  `provenance: "computed"`. The response also carries the run's `symmetry` record and the reflection operator for each
  mirror plane: a position sign vector, a vector-field sign vector and `scalar: "unchanged"`.
- `GET .../cfd-runs/{run_id}/fields-3d`, next to the existing `/fields` route and with the same scope and state checks.
- A frontend panel, `CfdField3dPanel.tsx`, shown next to the 2D slice for a finished run. It uses three.js (the existing
  dependency) and offers: a field selector (p, |U|); a colour legend with units; orbit controls; a "Show full pipe" toggle
  that is offered only when `symmetry.mirror_planes` is present; and a click probe that reports the nearest-vertex value,
  its coordinates and its provenance.

Out of scope (binding non-goals):
- Full-volume export, streamlines, iso-surfaces, axisymmetric wedge revolve, run-to-run 3D comparison.
- Any change to the existing `pipe_fields` export, its reader, `/fields` or `CfdFieldSlicePanel.tsx`.
- Backfilling earlier runs. A run without the 3D export or without `symmetry` metadata reports `unavailable` with a
  plain reason.
- New solver, mesh or physics capability; geometries other than `tube_run`.

## Design constraints

- Coordinates are in metres in the case frame generated by `casegen`: x is the pipe axis from the inlet (x = 0) to the
  outlet (x = L), and the quarter lies in y ≥ 0, z ≥ 0. `p` is kinematic pressure (m2/s2) and `U` is in m/s, as in
  `field_export._UNITS`.
- Reflection across y = 0 maps position (x, y, z) to (x, −y, z) and U to (Ux, −Uy, Uz). Reflection across z = 0 maps
  position to (x, y, −z) and U to (Ux, Uy, −Uz). The full pipe uses four copies: identity, y, z, and y∘z. Scalars are
  unchanged. Mirrored triangles reverse their winding so normals stay outward.
- The frontend applies only the operators that the backend returned. It never invents mirror planes. Without
  `symmetry.mirror_planes` there is no mirror toggle.
- Reconstructed geometry must look different from computed geometry: a "Mirrored from the computed quarter, not
  computed" badge whenever it is visible, and probe text that names the mirror plane and the computed source point.
- Size limits match the 2D reader: the combined computed surfaces stay within `MAX_POINTS` / `MAX_CELLS`. If they don't,
  the response is `too_large` and is not truncated. Malformed or non-finite data refuses the export with a reason. Each
  file is limited by `MAX_FILE_BYTES`.
- The extra function object changes the generated `controlDict`, so every pinned case digest or golden-text test fixture
  that covers it is updated deliberately in the same PR. Existing runs on disk are not rewritten.
- No new dependency, no schema migration (run state stays in `run.json`), and no provider or AI call.

## Acceptance criteria

1. A newly generated case `controlDict` contains `pipe_fields_3d` with the three patches and three x-normal cutting
   planes at 0.25 L, 0.5 L and 0.75 L. `pipe_fields` is unchanged byte for byte.
2. A run started after this change has the exact `symmetry` record in `run.json`.
3. `/fields-3d` returns `available` with six computed surfaces, the units above and correct operators for a fixture
   export. It returns `unavailable` for a run that is not finished, has no 3D export or has no `symmetry` metadata. It
   returns `too_large` above the limits.
4. The operators in the response are exactly the sign vectors listed in Design constraints, and a test asserts them
   against a hand-computed reflected point and velocity.
5. The panel renders the computed quarter, switches between p and |U| with the legend updating, and shows the full pipe
   only through the toggle, with the badge. A probe on a mirrored vertex reports the value of its computed source,
   with the reflected U component negated and p equal.
6. Real proof: one C1 `tube_run` executed with the pinned OpenFOAM as a registered `relay_jobs` job. The evidence records
   the 3D export file sizes, point and cell counts and the `/fields-3d` payload size. A clean-profile Chromium walk
   reaches the panel from `/` using visible controls only, toggles the full pipe, probes a computed vertex and a mirrored
   vertex, records zero page errors and records the time to first render.
